# CodexStudy: Game Demo Automation

一个运行在 Windows 前台的单机游戏示教自动化原型。程序同步录制指定游戏客户区与键鼠输入，将示教整理为可人工校准的关键状态，并导出 MaaFramework Pipeline v2 任务包。

本项目面向玩家有权自动化的本地单机游戏。请勿用于联网模式、排行榜、线上经济、带反作弊或游戏条款禁止自动化的场景。

## 当前能力

- 图形化完成“录制 → 校准并导出 → 选择任务包 → 启动 Maa 执行”。
- 录制画面以及键盘、鼠标按下/释放事件，包括 `Esc`、WASD 和鼠标点击。
- 支持固定 Maa 录制尺寸：
  - `16:9`：1280×720
  - `4:3`：960×720
- 自动将录制区域吸附到同一 Windows 窗口的完整客户区。
- 从示教中提取关键状态，并允许人工修改状态名称、ROI 和模板匹配阈值；默认阈值为 `0.5`。
- 导出目录由用户选择，导出的任务包会加入本地任务包列表。
- Maa 在目标窗口前台执行，键盘和鼠标使用 Win32 `LegacyEvent` 输入方式。
- 支持 `1–20` 次循环，并可设置 `0–3600` 秒的自定义轮间等待时间。
- 执行中或轮间等待时按 `F11`，可停止当前任务并取消剩余循环。
- 录制帧使用压缩存储，并对长录制的状态数量、键盘重复事件和跨状态按键保持进行整理。

## 运行要求

- Windows 10/11
- Python 3.11 或更高版本（当前在 Python 3.12 下验证）
- 目标游戏使用窗口化或无边框窗口，客户区尺寸必须与所选比例一致
- 执行期间目标窗口保持前台，分辨率、UI 缩放和按钮布局不要变化

安装开发、界面和 MaaFramework 依赖：

```powershell
py -m pip install -e ".[dev,ui,maa]"
```

## 启动图形界面

在仓库根目录运行：

```powershell
py -m game_demo_automation.workflow_gui_safe_v19
```

启动时选择录制比例：

- “是（Yes）”：16:9，1280×720
- “否（No）”：4:3，960×720
- “取消（Cancel）”：退出

## 使用流程

1. 将游戏切换到与所选比例一致的窗口客户区尺寸。
2. 点击“选择区域并开始录制”，在游戏窗口内拖动确定方向；录制框会固定为所选尺寸并吸附到客户区。
3. 完成一段完整示教后停止录制。
4. 点击“校准并导出”，逐项检查关键状态、ROI 和阈值，然后选择 Maa 任务包的保存目录。
5. 在“选择 Maa 任务包”中选择刚导出的任务包。
6. 设置循环次数和“每轮等待（秒）”。等待只发生在两轮之间，第一轮之前不会等待。
7. 将游戏保持在前台并启动 Maa 执行。需要终止时按 `F11`。

修改了示教、状态、输入时间轴或导出逻辑后，需要重新“校准并导出”。旧任务包不会自动更新。

## 数据与目录

- `recordings/`：本地示教录制，仅保存在本机，不提交到 Git。
- `tasks/`：本地导出的 Maa 任务包，仅保存在本机，不提交到 Git。
- `.game-demo-task-library.json`：本地任务包索引，不提交到 Git。
- 用户也可以在导出时选择仓库外的任意目录。

## 安全与已知限制

- 只支持前台执行；程序不会尝试绕过系统或游戏的后台输入限制。
- 关键状态识别依赖模板与 ROI。动态画面、特效、镜头变化或角色死亡后进入未知状态时，任务可能暂停或卡在当前环节。
- 第一/第三人称实时移动目前主要按示教时间轴执行，并不理解三维场景。
- 钓鱼、节奏提示等需要持续追踪移动目标的玩法，需要单独实现实时视觉闭环，不属于当前固定任务包能力。
- Maa 停止时可能输出 `stopping, ignore new post`。这是停止期间拒绝后续控制请求的内部日志；若任务和剩余循环已经停止，则属于预期行为。
